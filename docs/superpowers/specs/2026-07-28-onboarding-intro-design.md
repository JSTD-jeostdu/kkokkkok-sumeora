# 첫 방문 사용법 인트로 — 설계

## 배경
홈 화면은 히어로 인형과 "숨기러 가기" 버튼만 있고, 처음 온 사람에게 이 앱이 뭘 하는 곳인지 설명하는 요소가 없다. 게임 컨셉이 직관적이지 않은 편(사진에서 색 훔쳐 인형 위장 → 친구가 찾기)이라 첫 방문자의 이탈을 줄이고 프라이버시·무료·간편함에 대한 불안을 해소할 소개 화면이 필요하다.

## 범위
- 홈 화면 첫 방문 시 1회 자동으로 뜨는 스와이프 카드 오버레이(5장)
- 홈 화면 하단에 "사용법 다시보기" 링크로 언제든 재호출
- `localStorage` 플래그로 "본 적 있음" 상태 기억

**범위 밖:**
- 제작 화면·플레이 화면 안에서의 단계별 툴팁/코치마크 (별도 백로그)
- `?s=` 링크로 들어온 플레이어용 별도 안내 (이들은 홈을 거치지 않고 바로 플레이 화면으로 감 — 기존 라우팅 그대로 유지)
- 서버 측 로그/통계 (완전히 클라이언트 로컬 기능)

## 1. 데이터 모델
새 `localStorage` 키 1개만 사용, Firestore 변경 없음:

```
localStorage['kks_intro_seen'] = '1'
```

홈 화면 렌더 시 이 키가 없으면 오버레이를 자동으로 띄우고, 오버레이가 닫힐 때(건너뛰기·시작하기 모두) 키를 세팅한다.

## 2. 콘텐츠 — 5장 카드

| # | 아이콘 | 제목 | 본문 |
|---|---|---|---|
| 1 | 📷 | 사진 고르기 | 숨바꼭질할 사진 한 장을 골라요. 기기 안에서만 처리되고 서버에 원본이 올라가지 않아요 🔒 |
| 2 | 🎨 | 위장색 입히기 | 사진 속 색을 스포이드로 콕 찍어 인형에 발라요 |
| 3 | 🤫 | 몰래 숨기기 | 크기·회전·위치를 맞춰 사진 배경 속에 인형을 숨겨요 |
| 4 | 🔗 | 링크로 공유 | 가입 없이, 완전 무료로 링크 하나만 친구에게 보내면 끝! |
| 5 | 🔍 | 친구가 찾기 | 친구가 링크를 열면 카운트다운 후 제한시간 안에 인형을 찾아요 |

마지막 카드는 "다음" 대신 "시작하기" 버튼(오버레이 닫기 + 플래그 저장). 그 외 카드는 점 인디케이터 + "다음" 버튼. 상단 우측에 "건너뛰기"(✕) — 어느 카드에서든 즉시 닫고 플래그 저장.

## 3. 구조 · 인터랙션

**스와이프**: CSS `scroll-snap-type:x mandatory`를 쓰는 가로 스크롤 컨테이너에 카드 5개를 나열. 터치 스와이프는 브라우저 네이티브 동작을 그대로 사용(별도 제스처 JS 불필요).

**점 인디케이터**: 컨테이너의 `scroll` 이벤트에서 `scrollLeft / cardWidth`를 반올림해 현재 인덱스를 계산, 해당 점에 active 클래스 부여.

**다음/시작하기 버튼**: `scrollTo({left: (index+1)*cardWidth, behavior:'smooth'})`로 다음 카드까지 이동. 마지막 카드에서는 오버레이 닫기.

**건너뛰기(✕)**: 카드 위치와 무관하게 즉시 오버레이 닫기.

## 4. 노출 · 재호출 로직
- 홈 화면 초기화 시점(기존 홈 렌더 로직 마지막)에 `localStorage.getItem('kks_intro_seen')` 확인 → 없으면 오버레이 표시
- `?s=` 파라미터가 있어 플레이 화면으로 바로 가는 경우는 애초에 홈 초기화 코드를 안 타므로 자동으로 배제됨(기존 라우팅 변경 없음)
- 홈 화면 하단(공통 푸터 바로 위)에 작은 텍스트 링크 `사용법 다시보기` 추가 → 클릭 시 언제든 같은 오버레이를 다시 열되, 이번엔 닫아도 플래그를 다시 세팅할 뿐 상태를 지우지 않음(이미 세팅돼 있던 값 유지)

## 5. 스타일
- 오버레이 배경은 반투명 딤(`rgba(0,0,0,.5)` 톤) + 카드 자체는 기존 `.cut-card`(가위 점선 카드) 스타일 재사용 → 새 컴포넌트처럼 보이지 않고 기존 디자인 언어와 통일
- 카드 안 아이콘은 이모지(기존 갤러리·패널 제목에서 이미 쓰는 방식과 동일 — 별도 이미지 에셋 불필요)
- `prefers-reduced-motion` 사용자는 `scroll-behavior:auto`로 스무스 스크롤 애니메이션 생략(기존 방침과 동일)
- 탭 영역(다음/시작하기/건너뛰기/점) 44px 이상 유지

## 6. 에러 처리
- `localStorage` 접근 자체가 막힌 환경(프라이빗 모드 등에서 드물게 발생) → `try/catch`로 감싸고 실패 시 매번 오버레이가 뜨는 정도로 폴백(치명적이지 않음, 별도 안내 불필요)

## 확인된 제약
- Firestore·인증·기존 라우팅 로직에 변경 없음 — 순수 클라이언트 UI 추가라 배포된 데이터 포맷과 무관하고 되돌리기 쉬움(CLAUDE.md 크레딧 절약 방침상 "작고 리스크 낮은 변경"에 해당)
- 오버레이는 홈 화면 DOM에만 존재 — 제작/플레이 화면에는 영향 없음

## 영향받지 않는 것
- `stages`/`users` 컬렉션 및 Firestore 규칙
- `?s=` 라우팅, 플레이/제작 플로우 전체
- 기존 로그인·프로필·갤러리 로직
