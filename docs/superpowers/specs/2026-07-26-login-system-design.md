# 로그인 시스템 — 설계

## 배경
현재 앱은 Firebase 익명 인증(`signInAnonymously`)만 쓴다. 사용자에게 보이는 로그인 화면·계정 개념이 전혀 없고, 스테이지를 저장할 때 딱 한 번 보여주는 공유 링크·결과 보기 링크·삭제키를 잃어버리면 본인이 만든 스테이지도 다시 관리할 방법이 없다.

이번 작업은 (1) 제작자가 자기 스테이지를 잃어버리지 않고 관리할 수 있게 하고, (2) 향후 랭킹·친구 등 프로필 기반 기능을 얹을 수 있는 최소한의 사용자 식별 토대를 마련한다.

## 범위
- Google 로그인(선택 사항, 어디서도 강제하지 않음)
- "내 스테이지" 목록 화면(보기·공유 링크 다시 보기·삭제)
- 익명 세션 → 구글 계정 전환 시 데이터 병합(덮어쓰기 금지)
- Firestore 보안 규칙 확장(목록 조회·소유권 이전·삭제 강화)

**범위 밖** (백로그):
- 카카오 로그인 등 추가 소셜 제공자 — Firebase에서 OIDC 연동이 필요해 별도 조사 필요
- 닉네임 등 별도 프로필 문서(`users/{uid}` 컬렉션) — 이번엔 Firebase Auth의 `displayName`/`photoURL`을 그대로 사용
- 다른 기기에서 만든 익명 스테이지의 소급 병합 — 병합은 "로그인을 시도한 그 브라우저 세션"에서만 일어남(아래 제약 참고)
- 랭킹·친구 등 프로필 기반 신기능 자체 — 이번 작업은 토대만 마련

## 1. 인증 흐름

- **로그인 방식**: Firebase Auth의 Google 제공자 하나만. 카카오톡 인앱 브라우저 등 모바일 환경에서 팝업이 막히는 경우가 많아 `signInWithPopup` 대신 **`signInWithRedirect`**를 사용하고, 페이지 로드 시마다 `getRedirectResult()`로 리다이렉트 복귀를 확인한다.
- **계정 연결(익명 → 구글) 로직**:
  1. 로그인 버튼 클릭 시, 현재(익명) 유저에 `linkWithCredential(구글 credential)` 시도
  2. **성공** (이 구글 계정을 이 앱에서 처음 씀) → UID가 그대로 유지되므로 지금까지 만든 스테이지가 자동으로 전부 "내 것"이 된다. 별도 이관 작업 불필요.
  3. **실패** (`auth/credential-already-in-use` — 이 구글 계정으로 다른 기기·세션에서 이미 로그인한 적 있음) →
     a. **아직 익명 세션으로 인증된 상태에서** `where('creatorUid','==',현재 익명 uid)`로 내가 만든 스테이지를 모두 조회
     b. 각 문서의 `creatorUid`를 (에러 객체에 포함된) 기존 구글 계정 UID로 업데이트 — 이 시점엔 여전히 원래 익명 uid로 인증돼 있고, 그 uid가 문서의 현재 `creatorUid`와 일치하므로 규칙상 허용됨
     c. 이관이 끝난 뒤에야 `signInWithCredential`로 기존 구글 계정으로 전환
     d. 이 순서(먼저 넘기고 나중에 전환) 덕분에 어느 시점에도 데이터가 유실되지 않는다 — 이관 도중 실패해도 여전히 익명 uid로 로그인된 상태라 스테이지 접근이 끊기지 않는다.
- **로그아웃**: `firebase.auth().signOut()` 후 곧바로 새 익명 세션 재확립(빈 상태로 두면 저장 등 기존 기능이 깨짐).

## 2. Firestore 규칙 확장 (`firestore.rules`)

```
// list: 공개 갤러리(기존) + 내 스테이지 목록(신규) 둘 다 허용
allow list: if resource.data.isPublic == true
  || (request.auth != null && resource.data.creatorUid == request.auth.uid);

// update: 기존 stats/taps + 신규 creatorUid 이전(병합용, 반드시 본인 소유일 때만)
allow update: if request.auth != null && (
  request.resource.data.diff(resource.data).affectedKeys().hasOnly(['stats','taps'])
  || (request.resource.data.diff(resource.data).affectedKeys().hasOnly(['creatorUid'])
      && request.auth.uid == resource.data.creatorUid)
);

// delete: 기존엔 "인증만 되면 누구나" 삭제 가능했던 허점을 본인 소유로 강화 (부수적 보안 개선).
// 삭제키 UI는 유지하되, 규칙 차원에서도 소유자 본인만 삭제되도록 이중 방어.
allow delete: if request.auth != null && request.auth.uid == resource.data.creatorUid;
```

`creatorUid` 이전은 "현재 소유자가 자기 콘텐츠를 다른 자기 계정으로 넘기는" 동작이라, 다른 사람 소유 문서를 가로챌 수는 없다(규칙이 `request.auth.uid == resource.data.creatorUid`로 이미 소유자 본인임을 요구).

## 3. 화면 · UI

- **로그인 진입점**: 홈 화면 상단(히어로 인형 위쪽)에 작은 링크.
  - 로그아웃 상태: "로그인"
  - 로그인 상태: "OO님 · 로그아웃" (구글 계정 `displayName`)
- **내 스테이지 화면** (신규, `screen-home`/`screen-maker`와 동급의 새 섹션): 로그인 상태에서만 진입 가능.
  - 카드 목록. 공개 갤러리와 달리 본인 소유라 썸네일 블러 없음(정답 위치는 여전히 노출 안 함, 사진 자체만 원본 톤)
  - 카드마다: 도전 수, 클릭 시 액션 3가지
    - **보기**: 제작자 결과 보기 화면으로 이동 (정답 위치·히트맵)
    - **공유 링크 다시 보기**: 모달로 `?s=` 링크 재노출 (삭제키는 재노출하지 않음 — 로그인 소유자는 키 없이 삭제 가능하므로 불필요)
    - **삭제**: 삭제키 입력 없이 확인 후 즉시 삭제 (로그인 자체가 소유권 증명)
- **기존 저마찰 제작 플로우는 변경 없음** — "사진 고르기 → 바로 제작 시작"에 로그인이 끼어들지 않는다.

## 4. Firebase 콘솔 설정 (배포 절차 추가)

Google 로그인 제공자는 코드로 배포할 수 없고 콘솔 수동 활성화가 필요하다. 기존 "Authentication 익명 로그인 활성화" 단계 옆에 다음을 추가:

> Authentication → Sign-in method → **Google** 활성화 (지원 이메일 설정 필요)

## 확인된 제약 (자기 검토 결과 명시)

- **병합은 동일 브라우저 세션에서만 동작한다.** 다른 기기·다른 브라우저·시크릿 창에서 만든 익명 스테이지는 로그인해도 자동으로 나타나지 않는다 — 그 세션의 Firebase Auth 로컬 상태(익명 uid)가 남아있어야 병합 로직이 실행되기 때문. 소급 복구 수단은 이번 범위 밖.
- **기존(오늘 이전) 스테이지**도 마찬가지로, 그걸 만든 브라우저 세션이 살아있고 그 세션에서 로그인을 시도해야만 병합된다. 이미 만들어진 지 오래돼 로컬 스토리지가 지워졌다면 병합 불가 — 새 마이그레이션 스크립트 없이도 안전하게(강제로 아무 것도 하지 않고) 넘어가는 설계.
- 삭제 규칙 강화(`allow delete`)는 기존 UX를 깨지 않는다 — 지금까지도 삭제는 항상 스테이지를 만든 바로 그 브라우저 세션(즉 `creatorUid`와 같은 익명 uid)에서만 이뤄져 왔기 때문에, 실사용 흐름에는 영향이 없고 다른 사람이 ID만 알아도 삭제할 수 있었던 허점만 막는다.

## 영향받지 않는 것
- 익명 사용자의 플레이·제작·공유 흐름 전체
- 기존 공개 갤러리(`isPublic`), 이어달리기 체인 CTA 기능
- Storage 미사용 원칙, 단일 파일 `index.html` 구조
